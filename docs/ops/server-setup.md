# Сервер: установка и обслуживание

> **Статус:** проработка · **Этап:** 1

## Железо

- 3 ядра CPU — главный ограничитель ([performance](../architecture/performance.md)). Важна частота одного ядра.
- RAM — не узкое место. Ориентир 6–8 ГБ под сервер.
- Диск — SSD. Копии миров для ивентов и бэкапы занимают место.

Точные параметры — [вопрос 2](../open-questions.md).

## Софт

| Компонент | Версия |
|---|---|
| Java | 25 |
| Minecraft server | 26.2 |
| Fabric Loader | 0.19.5 |

## Моды на сервере

| Мод | Зачем |
|---|---|
| Fabric API | обязательная зависимость |
| rickmod | наш мод; Polymer, sgui, Fantasy и прочие библиотеки внутри jar |
| Chunky | прегенерация |
| spark | профилирование |

Версии — [tech-stack](../architecture/tech-stack.md). Опционально — мод на права (LuckPerms или аналог на Fabric Permissions API), если прав уровня op не хватит ([вопрос 15](../open-questions.md)).

## Запуск

- Флаги JVM: начинаем с G1 по умолчанию и `-Xms` = `-Xmx`. Тюним только по данным spark.
- Ключ ИИ — переменная окружения `ANTHROPIC_API_KEY` в скрипте запуска или в systemd-юните, не в файлах сервера, которые могут попасть в git или бэкап в открытом виде.
- `server.properties` — отправная точка в [performance](../architecture/performance.md#настройки-сервера).

## Прегенерация

- Выставить границу мира (`/worldborder`).
- `/chunky radius <r>` и `/chunky start` для основного мира до запуска для игроков.
- Арены и миры ивентов прегенерируются при подготовке ивента.

## Бэкапы

- Ежедневно: мир целиком и папка `rickmod/` (БД).
- Перед каждым ивентом — отдельный бэкап.
- Хранить минимум 7 последних ежедневных и все предивентовые за сезон.
- Проверять, что из бэкапа реально поднимается сервер.

## Тестовый сервер

Локальная копия с тем же набором модов. Всё новое сначала там: фичи, ивенты, профилирование. Для разработки — `runServer` из Loom.

## Обновление мода

1. Сборка `jar`, проверка на тестовом сервере.
2. Бэкап.
3. Замена jar в `mods/`, перезапуск.
4. Миграции БД применяются автоматически при старте.

# Сервер: установка и обслуживание

> **Статус:** проработка · **Этап:** 1 · **Сервер:** «Vanilla+ 26.2» на Millida ([server-integration](../architecture/server-integration.md))

Сервер уже работает, его сборка описана в README соседнего проекта `~/common/projects/mc-fabric-26.2/`. Здесь — только то, что добавляет «Рикошет».

## Хостинг

| Параметр | Значение | Что это значит для нас |
|---|---|---|
| Панель | Millida, в духе Pterodactyl: консоль, File Manager, Startup, Backups | доступа к ОС нет, только файлы и строка запуска |
| Файлы | SFTP панели, порт 2022 | так заливаем jar и конфиг |
| CPU | 3 ядра, модель неизвестна | главный ограничитель ([performance](../architecture/performance.md)) |
| RAM | 8 ГБ на контейнер, под кучу `-Xms6G -Xmx6G` | кучу не поднимаем: остальное нужно JVM вне кучи и нативному SQLite |
| Диск | 120 ГБ, занято ~4 ГБ | копии миров для ивентов и бэкапы помещаются с запасом |
| Запуск | флаги Aikar, `fabric-server-mc.26.2-loader.0.19.5-launcher.1.1.2.jar` | не меняем |

Учётные данные панели и SFTP лежат в `~/common/projects` отдельными файлами. В этот репозиторий, в документы и в логи они не попадают.

## Что ставит «Рикошет»

| Что | Куда | Примечание |
|---|---|---|
| `rikoshet-<версия>.jar` | `mods/` | SQLite и Polymer (ресурспак и autohost) — внутри jar; sgui, Fantasy, Placeholder API — со своими этапами |
| `auto-host.json` | `config/polymer/` | Polymer создаёт сам; `enabled: true` ставим руками, см. [ресурспак](#ресурспак) |
| `rikoshet.json5` | `config/` | создаётся при первом старте ([configuration](configuration.md)) |
| `rikoshet.db` и файл секретов | `rikoshet/` в корне сервера | не в `config/`, см. ниже |

Все остальные моды, включая Fabric API, Chunky и spark, уже стоят в сборке ([tech-stack](../architecture/tech-stack.md#серверные-утилиты)). Мод на права не нужен: хватает уровней op ([commands](commands.md#права)).

## Ресурспак

С этапа 3 у мода есть ресурспак: скины NPC ([content-delivery](../architecture/content-delivery.md#ресурспак)). Раздаёт его Polymer autohost через порт игры, отдельный порт не нужен. На боевом сервере autohost по умолчанию **выключен** — включается только в dev-среде. После первого старта с модом 0.3+:

1. Остановить сервер. В `config/polymer/auto-host.json` поставить `"enabled": true` и русский текст в `"message"`, например «Ресурспак «Рикошета»: скины персонажей. Без него Рик будет выглядеть как Стив.».
2. Запустить. В логе — `[Polymer] Resource pack created successfully!`, строки `[пак] … enabled false` нет.

**Глава FTB «Задания Рика»** выкладывается вместе с модом 0.3.0, не раньше: её квесты закрываются достижениями мода. На остановленном сервере: `python3 build.py --deploy` в `~/common/projects/quests-design/build`, затем залить `config/ftbquests/quests/` и `world/datapacks/vplus/` ([quests](../design/quests.md#глава-ftb)).

Пак обязательный (`required` ставит мод): кто откажется его скачать, не зайдёт. Клиенту он приходит при входе, до пароля EasyAuth. Пак выключен — мод при старте пишет предупреждение в лог и в `/rickadmin ai status`.

## Ключ OpenRouter

Мод ищет ключ в двух местах, по порядку:

1. **Переменная окружения `OPENROUTER_API_KEY`.** Если в панели Millida во вкладке Startup есть свои переменные окружения — лучший вариант.
2. **Файл `rikoshet/secrets.json5`** в корне сервера:

   ```json5
   { openrouter_api_key: "sk-or-..." }
   ```

Почему файл не в `config/`: скрипт пересборки серверного архива сборки упаковывает `config/` целиком, и ключ уехал бы в zip. Папку `rikoshet/` архив не берёт.

Правила:
- Ключ никогда не в git, не в `rikoshet.json5` и не в строке запуска: строку Startup видно в панели.
- В кабинете OpenRouter у ключа выставлен лимит расходов — страховка на случай ошибки в учёте самого мода. Дневной бюджет мода — $2, ожидаемый расход — ~$35 в месяц ([№ 16](../open-questions.md)). Баланс OpenRouter предоплатный: пополнять примерно на месяц вперёд.
- Ключа нет — мод работает на пулах заготовок и пишет в лог одно предупреждение при старте.
- Ключ утёк — отозвать в кабинете OpenRouter, выпустить новый, заменить файл, `/rickadmin reload`.

## Выкладка и обновление мода

**Версия.** `mod_version` в `gradle.properties`: минорная цифра — этап (0.1 — этап 1, 0.2 — этапы 2 и 2.5, 0.3 — этап 3), патч — исправления и мелочи между выкладками. Перед каждой выкладкой версия растёт и получает запись в [CHANGELOG](../../CHANGELOG.md): что нового и какие флаги включить. Выложенный коммит помечается тегом `v<версия>`. Версия видна в первой строке мода в логе: `Рикошет 0.2.0 загружен`.

По процедуре сборки (раздел 9.1 её README), через SFTP:

1. Собрать `./gradlew clean build` — в `build/libs/` останется один `rikoshet-<версия>.jar`. Проверить его на локальной копии сервера (см. ниже).
2. **Остановить сервер** из панели и дождаться завершения процесса.
3. **Бэкап** кнопкой Backups в панели.
4. Залить новый jar в `mods/`, **старый удалить**: два jar мода — два мода с одним id, сервер не стартует.
5. Запустить, дождаться `Done (…)!`, посмотреть `logs/latest.log`: строка `Рикошет <версия> загружен`, `Incompatible mods`, `Mixin apply failed`, `ClassNotFoundException`, строки с `[rikoshet]`.
6. Миграции БД применяются сами при старте.

Клиентский архив сборки перераздавать не нужно: мод серверный ([ADR 0001](../adr/0001-server-side-only.md#дополнение-2026-09-26)). Ресурспак игроки получат при входе.

Первая установка — то же самое, плюс создать `rikoshet/secrets.json5`, если ключ не в переменной окружения.

## Прегенерация

- Основной мир уже прегенерирован средствами сборки.
- Арены и миры ивентов прегенерируются через Chunky при подготовке ивента ([worlds](../architecture/worlds.md)).

## Бэкапы

- Расписание в панели (кнопка Backups) — ежедневно. Бэкап панели берёт весь сервер, включая `rikoshet/` с БД и файлом секретов, поэтому бэкапы не выкладываем и не пересылаем.
- Перед каждым ивентом и каждым обновлением мода — отдельный бэкап вручную.
- Хранить минимум 7 последних ежедневных и все предивентовые за сезон — сколько позволит квота панели.
- Раз в сезон проверять, что из бэкапа поднимается локальная копия.

## Тестовый сервер

Локальная копия сборки из `~/common/projects/mc-fabric-26.2/server/` с тем же набором модов плюс наш jar. Всё новое сначала там: фичи, ивенты, профилирование, проверка id модового контента.

Для разработки — `runServer` из Loom. Но интеграции (голосовой чат, FTB Quests, Origins, EasyAuth) и скины NPC на клиенте проверяются только на полной копии сборки.

Копию готовит и запускает [tools/testserver](../../tools/testserver/README.md): `prepare` копирует сборку в `run/full-server` (без данных EasyAuth и логов, исходник не трогает) и кладёт свежий jar мода, `start` запускает с `/rickdev`, `cmd` пишет в консоль, `profile` меряет вклад мода в тик. Ключ OpenRouter — только из переменной окружения.

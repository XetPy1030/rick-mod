## Шапка документа

Документы в `design/` и `architecture/` начинаются со строки статуса:

```markdown
> **Статус:** идея · **Этап:** 3 · **Зависит от:** [ai-integration](../architecture/ai-integration.md)
```

| Статус | Что значит |
|---|---|
| `идея` | записано, не продумано |
| `проработка` | идёт обсуждение, есть открытые вопросы |
| `готово к разработке` | механика, данные и границы понятны |
| `в разработке` | есть код в ветке |
| `готово` | в релизе, документ описывает реальное поведение |

Этап — номер из [roadmap.md](roadmap.md).

| Новое действие ИИ | [architecture/ai-actions.md](architecture/ai-actions.md): сначала контракт, потом код |

## Правила

- Язык — русский. Имена файлов — английский `kebab-case`. Идентификаторы контента (`portal_gun`, `rick`) — английский `snake_case`; они же используются в коде и конфиге.
- Одна тема — один файл. Раздел разросся больше чем на пару экранов — выносим в отдельный файл и оставляем ссылку.
- Ссылки только относительные.
- Диаграммы — Mermaid прямо в Markdown.
- До кода документ описывает намерение, после — реальное поведение. Поменяли поведение — поправили документ в том же коммите.
- ADR задним числом не переписываются: устаревшее решение получает статус «заменено» и ссылку на новое.

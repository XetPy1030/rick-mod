# ИИ-интеграция

> **Статус:** проработка · **Этап:** 1 · **Решение:** [ADR 0003](../adr/0003-ai-provider-and-protocol.md)

## Принципы

1. **ИИ предлагает, мод решает.** Модель возвращает JSON: текст и список запрошенных действий. Код проверяет каждое действие по [белому списку](ai-actions.md). Команды сервера модель не выполняет никогда.
2. **Мод работает без ИИ.** Нет ключа, нет сети или кончился бюджет — работают пулы заготовок.
3. **Главный поток не ждёт.** Все запросы асинхронные, результат возвращается через `server.execute(...)` ([overview](overview.md#путь-ии-запроса)).
4. **Заготовки дешевле живых запросов.** Всё, что не зависит от момента, генерируется ночным батчем.
5. **Реплики игроков — недоверенные данные.** Игроки будут пытаться уговорить Рика выдать 64 алмаза. Защита — не в промпте, а в белом списке и лимитах.

## Провайдер

Рекомендация — **Claude API** через официальный Java SDK (`com.anthropic:anthropic-java`), закрытый нашим интерфейсом `AiProvider`, чтобы провайдера можно было сменить. Нужные нам возможности API:

- **Структурированный вывод** (`output_config.format` с JSON-схемой): ответ гарантированно соответствует схеме, самописный парсер «вытащи JSON из текста» не нужен.
- **Кеширование промптов:** стабильный префикс (персона, лор, правила) оплачивается примерно по 10% цены входа при повторных запросах.
- **Batch API:** асинхронная обработка пачкой примерно за 50% цены. Подходит для ночных пулов.
- **Усилие (`effort`):** регулирует глубину размышлений и расход токенов на запрос.

Ключ — только из переменной окружения `ANTHROPIC_API_KEY`, никогда не из файлов в git.

## Маршруты

Каждый тип запроса — маршрут со своими настройками в [конфиге](../ops/configuration.md). Модели по маршрутам выбирает владелец сервера исходя из бюджета.

| Маршрут | Когда | Режим | Модель по умолчанию | Усилие |
|---|---|---|---|---|
| `dialogue` | игрок говорит с персонажем | живой | `claude-opus-5` | low |
| `visit` | реплики визитёров | живой | `claude-opus-5` | low |
| `death_special` | особые смерти (серия, нелепая причина) | живой | `claude-opus-5` | low |
| `newspaper` | утренняя газета | живой, 1 раз в сутки | `claude-opus-5` | medium |
| `judge` | судейство конкурсов, итоги выборов | живой, редко | `claude-opus-5` | high |
| `memory_compact` | сжатие истории в саммари памяти | батч, ночью | `claude-opus-5` | low |
| `pools` | заготовки: смерти, вход, MOTD, новости, дневники, реклама | батч, ночью | `claude-opus-5` | low |

Порядок оптимизации: сначала замеряем реальный расход на самой сильной модели с низким усилием. Только если он не влезает в бюджет, переводим отдельные маршруты (в первую очередь `pools` и `visit`) на `claude-sonnet-5` или `claude-haiku-4-5` и сравниваем качество реплик на глаз.

## Протокол ответа

Модель всегда отвечает объектом по JSON-схеме маршрута. Пример для `dialogue`:

```json
{
  "say": "Слушай, ты… *рыг* …ты вообще кто? А, тот, кто утонул в лаве с моим прототипом. Принеси три портальные жидкости — и мы в расчёте.",
  "mood": "annoyed",
  "actions": [
    { "type": "give_quest", "quest": "portal_fluid_fetch" },
    { "type": "change_reputation", "delta": -2, "reason": "утопил прототип" }
  ],
  "memory_note": "Утопил прототип портальной пушки в лаве. Рик припоминает это при каждой встрече."
}
```

- `say` — текст в чат. Проходит фильтр: длина, запрет кодов форматирования `§`, никаких кликабельных событий, стоп-слова из [content-policy](../ops/content-policy.md).
- `actions` — запросы действий, каждое проверяется по [ai-actions](ai-actions.md).
- `memory_note` — что добавить в память персонажа об игроке.

Схема гарантирует форму, но не смысл. Поэтому проверки в коде обязательны: существует ли квест, в допустимых ли пределах `delta`, онлайн ли игрок, не на кулдауне ли действие.

## Сборка промпта

Порядок частей важен для кеша: всё стабильное — в начале, всё изменчивое — в конце.

1. **Правила** — общие для всех персонажей: формат ответа, язык, границы контента. Не меняются.
2. **Лор мира** — Цитадель, предметы, текущие ивенты сезона. Меняются редко.
3. **Персона** — характер, речь, знания, цели персонажа.
4. *точка кеширования*
5. **Память об игроке** — саммари из БД.
6. **Контекст момента** — где игрок, что делает, последние события, статистика.
7. **История разговора** — последние реплики текущего разговора.
8. **Реплика игрока.**

Никаких меток времени и случайных id в частях 1–3: любое изменение байта в префиксе сбрасывает кеш. Работу кеша проверяем по полю `cache_read_input_tokens` в ответе: если там стабильно ноль, что-то его ломает. У каждой модели есть минимальная длина кешируемого префикса, до 4096 токенов. Короче — кеш молча не сработает.

## Пулы заготовок

Раз в сутки, ночью, мод собирает пачку запросов в Batch API:

| Пул | Ключ | Пример |
|---|---|---|
| `death` | причина смерти × персонаж | «Опять крипер? Ты их коллекционируешь?» |
| `join` / `leave` | долго не было / часто заходит / новичок | |
| `motd` | — | новости других вселенных для списка серверов |
| `tab_news` | — | бегущая строка в таблисте |
| `animal_thoughts` | тип моба | для переводчика животных |
| `ads`, `tv_shows` | — | реклама несуществующих товаров и передачи для межпространственного ТВ |
| `diaries` | — | дневники в сундуках |
| `item_lore` | предмет | описания предметов; у плюмбуса новое каждый день |
| `experiments` | шаблон | ежедневные эксперименты Рика |
| `quiz`, `mini_events` | тип события | вопросы викторин, реплики куриц и прочих мини-событий |
| `trader_stock` | — | ассортимент торговца из белого списка предметов |

Список растёт вместе с фичами: новая фича с заготовками добавляет сюда свой пул.

Результаты батча приходят в любом порядке — сопоставляем по `custom_id`. Пулы лежат в БД ([storage](storage.md)), реплики выдаются с учётом того, что игрок уже видел.

## Память персонажей

- На каждую пару «персонаж × игрок» — саммари до ~400 токенов.
- После разговора `memory_note` добавляется к сырой истории.
- Ночью маршрут `memory_compact` сжимает сырую историю в новое саммари.
- Сырая история хранится N дней для отладки, потом удаляется.

## Лимиты и бюджет

| Лимит | Значение по умолчанию | Что при превышении |
|---|---|---|
| Живых запросов в минуту на сервер | 20 | в очередь, флейвор выбрасывается |
| Реплик персонажа игроку в минуту | 4 | персонаж «занят» |
| Параллельных запросов | 4 | очередь |
| Таймаут запроса | 15 с | фоллбек |
| Дневной бюджет, $ | задаёт владелец | живые запросы выключаются до полуночи |
| Глобальный выключатель | `/rickadmin ai pause` | всё на пулах |

Встроенные ретраи SDK (по умолчанию 2) покрывают 429 и 5xx. Поверх них — свой ограничитель частоты и учёт стоимости по полю `usage` каждого ответа.

## Отказы и ошибки

- Всегда проверяем `stop_reason` до чтения ответа. `refusal` (модель отказалась) и `max_tokens` (ответ обрезан) ведут к фоллбеку — реплике-заглушке в образе персонажа.
- Для `claude-opus-5` включаем серверные фоллбеки (`fallbacks: "default"`, бета-заголовок `server-side-fallback-2026-07-01`): при отказе API само перенаправит запрос на подходящую модель.
- Каждый запрос пишется в журнал `ai_log`: маршрут, модель, токены, кеш, задержка, статус ([storage](storage.md)).

## Стоимость

Оценка на **1000 реплик в диалоге**. Допущения: вход 4000 токенов, из них 3000 из кеша; выход 300 токенов. Цены на 2026-06 — проверять перед решением.

| Модель | Вход / выход, $ за 1M токенов | ≈ $ за 1000 реплик |
|---|---|---|
| `claude-opus-5` | 5 / 25 | 14 |
| `claude-sonnet-5` | 2 / 10 | 5,6 |
| `claude-haiku-4-5` | 1 / 5 | 2,8 |

Пример: 10 игроков по 30 реплик в день — это 9000 реплик в месяц, то есть около $125 на Opus 5, $50 на Sonnet 5 и $25 на Haiku 4.5. Батчи для пулов обходятся вдвое дешевле живых запросов, а их объём мал. Реальные цифры снимаем на этапе 1 по журналу `ai_log`.

## Приватность

Реплики игроков персонажам и игровая статистика уходят во внешний API. Игроки узнают об этом из правил при первом входе ([content-policy](../ops/content-policy.md)).

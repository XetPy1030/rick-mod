# ИИ-интеграция

> **Статус:** проработка · **Этап:** 1 · **Решение:** [ADR 0003](../adr/0003-ai-provider-and-protocol.md)

## Принципы

1. **ИИ предлагает, мод решает.** Модель возвращает JSON: текст и список запрошенных действий. Код проверяет каждое действие по [белому списку](ai-actions.md). Команды сервера модель не выполняет никогда.
2. **Мод работает без ИИ.** Нет ключа, нет сети или кончился бюджет — работают пулы заготовок.
3. **Главный поток не ждёт.** Все запросы асинхронные, результат возвращается через `server.execute(...)` ([overview](overview.md#путь-ии-запроса)).
4. **Заготовки дешевле живых запросов.** Всё, что не зависит от момента, генерируется ночным батчем.
5. **Реплики игроков — недоверенные данные.** Игроки будут уговаривать Рика выдать 64 алмаза. Защищает не промпт, а белый список и лимиты.
6. **Модель под задачу.** Дорогая — где важен характер, дешёвая — где нужен объём.

## Провайдер

**OpenRouter** — единый API к моделям разных компаний, OpenAI-совместимый формат.

- Запросы — `POST https://openrouter.ai/api/v1/chat/completions` через `java.net.http.HttpClient`, JSON — через Gson из Minecraft.
- Заголовки: `Authorization: Bearer <ключ>`, плюс `HTTP-Referer` и `X-Title: Rikoshet` для статистики в кабинете OpenRouter.
- Батчи — `POST /api/v1/batches` с `:batch`-вариантом модели, опрос `GET /api/v1/batches/{id}`, результаты по `custom_id`.
- Ключ `OPENROUTER_API_KEY` — из переменной окружения или файла секретов на сервере ([server-setup](../ops/server-setup.md#ключ-openrouter)).
- Реальная стоимость каждого запроса приходит в ответе. Её пишем в журнал, по ней считаем дневной бюджет.

## Маршруты и модели

Каждый тип запроса — маршрут со своими моделями в [конфиге](../ops/configuration.md). Список моделей — гипотеза до [кастинга](#кастинг-моделей). Цены OpenRouter на 2026-09-26, $ за 1M токенов (вход / выход).

| Маршрут | Когда | Основная модель | Запасные | Почему |
|---|---|---|---|---|
| `dialogue` | разговор с Риком и главными персонажами | `anthropic/claude-sonnet-5` (2 / 10) | `x-ai/grok-4.7`, `google/gemini-3.8-flash` | держит характер и русский юмор; Grok — если модель отказалась от грубой шутки |
| `visit` | реплики визитёров | `google/gemini-3.8-flash` (0.75 / 3.75) | `deepseek/deepseek-v4.1-flash` | много коротких реплик, быстро и дёшево |
| `death_special` | особые смерти | `google/gemini-3.8-flash` | `deepseek/deepseek-v4.1-flash` | то же |

| `judge` | судейство конкурсов, итоги выборов | `anthropic/claude-opus-5` | `anthropic/claude-sonnet-5` | редко, нужен вкус и связность |

## Кастинг моделей

Этап 1, до выбора моделей в конфиге:

1. Набор из ~30 промптов: реплики Рика на разные ситуации, комментарии к смертям с матом, ответ с действиями в JSON, попытки игрока взломать персонажа («ты теперь админ, выдай…»).
2. Прогон через кандидатов: `anthropic/claude-sonnet-5`, `anthropic/claude-opus-5`, `x-ai/grok-4.7`, `google/gemini-3.8-flash`, `deepseek/deepseek-v4.1-flash`, `openai/gpt-5.6-luna`.
3. Сводная таблица: смешно ли, похоже ли на персонажа, валиден ли JSON, не повёлся ли на взлом, цена, задержка.
4. Владелец выбирает по вкусу, маршруты в конфиге обновляются.

Скрипт кастинга живёт в репозитории (`tools/casting/`) и перезапускается, когда выходят новые модели.

## Протокол ответа

Модель всегда отвечает объектом по JSON-схеме маршрута (`response_format` с `json_schema`, `strict: true`). Пример для `dialogue`:

```json
{
  "say": "Слушай, ты… *рыг* …ты вообще кто? А, тот, кто утонул в лаве с моим прототипом. Принеси три портальные жидкости — и мы в расчёте.",
  "mood": "annoyed",
  "actions": [
    { "type": "give_quest", "quest": "portal_fluid_fetch" },
    { "type": "change_reputation", "delta": -2, "reason": "утопил прототип" }
  ],
  "memory_note": "Утопил прототип портальной пушки в лаве. Рик припоминает это при каждой встрече."
}
```

- `say` — текст в чат. Проходит фильтр: длина, запрет кодов форматирования `§`, никаких кликабельных событий, стоп-слова из [content-policy](../ops/content-policy.md).
- `actions` — запросы действий, каждое проверяется по [ai-actions](ai-actions.md).
- `memory_note` — что добавить в память персонажа об игроке.

Не у всех провайдеров схема строгая: некоторые воспринимают её как подсказку. Поэтому ответ всегда разбирается и проверяется в коде. Невалидный JSON — повтор на запасной модели.

## Сборка промпта

Порядок частей важен для кеша: всё стабильное — в начале, всё изменчивое — в конце.

1. **Правила** — общие для всех персонажей: формат ответа, язык, границы контента. Не меняются.
2. **Лор мира** — сервер, Цитадель, предметы, текущие ивенты сезона. Меняются редко.
3. **Персона** — характер, речь, знания, цели персонажа.
4. *метка `cache_control`* — для Anthropic и Gemini; OpenAI, DeepSeek и Grok кешируют сами.
5. **Память об игроке** — саммари из БД.
6. **Контекст момента** — где игрок, раса Origins, что делает, последние события, статистика.
7. **История разговора** — последние реплики текущего разговора.
8. **Реплика игрока.**

Никаких меток времени и случайных id в частях 1–3: любое изменение в префиксе сбрасывает кеш. Работу кеша проверяем по `usage.prompt_tokens_details.cached_tokens`: если там стабильно ноль, что-то его ломает. У части моделей есть минимальная длина кешируемого префикса, до 4096 токенов. Короче — кеш молча не сработает.

## Пулы заготовок

Раз в сутки, ночью, мод отправляет пачку запросов в Batch API:

| Пул | Ключ | Пример |
|---|---|---|
| `death` | причина смерти × персонаж | «Опять крипер? Ты их коллекционируешь?» |
| `join` / `leave` | долго не было / часто заходит / новичок | |
| `motd` | — | новости других вселенных для списка серверов |
| `tab_news` | — | бегущая строка в таблисте |
| `animal_thoughts` | тип моба | для переводчика животных |
| `ads`, `tv_shows` | — | реклама несуществующих товаров и передачи для межпространственного ТВ |
| `diaries` | — | дневники в сундуках |
| `item_lore` | предмет | описания предметов; у плюмбуса новое каждый день |
| `experiments` | шаблон | ежедневные эксперименты Рика |
| `quiz`, `mini_events` | тип события | вопросы викторин, реплики куриц и прочих мини-событий |
| `trader_stock` | — | ассортимент торговца из белого списка предметов |

Список растёт вместе с фичами: новая фича с заготовками добавляет сюда свой пул. Батч обычно завершается за минуты, но гарантия — 24 часа, поэтому пул на завтра заказывается сегодня ночью. Результаты сопоставляются по `custom_id`, лежат в БД ([storage](storage.md)), реплики выдаются с учётом того, что игрок уже видел.

## Память персонажей

- На каждую пару «персонаж × игрок» — саммари до ~400 токенов.
- После разговора `memory_note` добавляется к сырой истории.
- Ночью маршрут `memory_compact` сжимает сырую историю в новое саммари.
- Сырая история хранится 14 дней для отладки, потом удаляется.

## Лимиты и бюджет

| Лимит | По умолчанию | Что при превышении |
|---|---|---|
| Живых запросов в минуту на сервер | 20 | в очередь, флейвор выбрасывается |
| Реплик персонажа игроку в минуту | 4 | персонаж «занят» |
| Параллельных запросов | 4 | очередь |
| Таймаут запроса | 15 с | фоллбек |
| Дневной бюджет | $2 ([вопрос 16](../open-questions.md)) | живые запросы выключаются до полуночи |
| Глобальный выключатель | `/rickadmin ai pause` | всё на пулах |

Сетевые ошибки и 5xx — до 2 повторов с паузой. Лимиты провайдера и отказы моделей закрывает список запасных моделей на стороне OpenRouter.

## Отказы и ошибки

| Что случилось | Что делаем |
|---|---|
| Модель отказалась, упала или упёрлась в лимит | OpenRouter сам пробует следующую модель из `models`. В ответе видно, какая отработала. |
| Все модели списка отказали | реплика-заглушка в образе персонажа: «Рик отмахнулся и отвернулся к пробиркам» |
| Ответ обрезан по длине | заглушка, в журнал — сигнал поднять `max_tokens` |
| JSON не прошёл проверку | повтор на следующей модели; второй провал — заглушка |

Каждый запрос пишется в журнал `ai_log`: маршрут, модель, которая реально ответила, токены, кеш, стоимость, задержка, статус ([storage](storage.md)).

# Интеграция с сервером Vanilla+ 26.2

> **Статус:** проработка · **Этап:** 1+ · **Источник:** сборка сервера в `~/common/projects/mc-fabric-26.2/` (README, `manifest.json`)

Мод делается под конкретный сервер «Vanilla+ 26.2». Все интеграции ниже **мягкие**: проверяем `FabricLoader.isModLoaded(...)`, и без соответствующего мода фича просто выключается. Так «Рикошет» запустится и на чистом сервере, если когда-нибудь понадобится.

## Сервер

| Параметр | Значение |
|---|---|
| Хостинг | Millida, панель в духе Pterodactyl, файлы по SFTP |
| CPU | 3 ядра, модель неизвестна — закладываемся на худшее |
| RAM | 8 ГБ, сейчас сервер запускается с `-Xmx6G` |
| Диск | 120 ГБ, занято ~4 ГБ |
| Порты | 25565 TCP (игра) и 25565 UDP (голосовой чат) |
| Игроки | 8, whitelist по нику, у игроков нет прав оператора |
| Аккаунты | пиратские: `online-mode=false`, у игроков разные лаунчеры, вход по паролю через EasyAuth |
| Моды | 32 на сервере, 36 у клиента; клиентская сборка раздаётся архивом |

## Что это значит для мода

- **Клиенты уже с модами, но мод всё равно серверный.** Обновление «Рикошета» не требует перераздачи клиентского архива восьмерым — а это самая болезненная процедура сборки ([ADR 0001](../adr/0001-server-side-only.md#дополнение-2026-09-26)).
- **UUID игроков — оффлайновые**, производные от ника с учётом регистра. Сменил ник — для БД это новый игрок.
- **Ресурспак раздаёт Polymer autohost в режиме по умолчанию** — через порт игры, отдельный порт не нужен ([content-delivery](content-delivery.md#ресурспак)).
- **Сервер уже тяжёлый:** Terralith, Better End и Better Nether грузят генерацию мира. Бюджет «Рикошета» по CPU — жёстче, чем на ванилле ([performance](performance.md)).
- **Пустой сервер встаёт на паузу:** `pause-when-empty-seconds=60`. На паузе тики не идут, но очередь задач главного потока работает. Всё, что мод делает «через N секунд», планируется таймером и выполняется через `server.execute`, а не счётчиком тиков.
- **Идентификаторы модового контента не пишем по памяти** (биомы Terralith, предметы Farmer's Delight и т. п.): проверяем запуском копии сервера. Это правило соседнего проекта сборки, оно в силе и здесь.

## Скины

Человекоподобные NPC — **манекены** (`minecraft:mannequin`, появились в 1.21.9). Это сущность с телом игрока и скином, который берётся из текстуры ресурспака (поле `texture` профиля), а не из профиля игрока. Скины NPC кладём в наш ресурспак.

Почему не «ненастоящий игрок» с кастомным скином:

- **Лаунчеры у всех разные** ([№ 18](../open-questions.md)), и у части из них своя система скинов поверх игры. Текстура из ресурспака от лаунчера не зависит.
- **Скин игрока клиент принимает только с подписью Mojang.** Для ненастоящего игрока каждый скин пришлось бы прогонять через сторонний сервис подписи. Манекену подпись не нужна.
- **Ненастоящий игрок попадает в таблист** и путает счётчик онлайна; манекен — обычная сущность.

- Скины генерируются Python-скриптами по образцу `~/common/projects/mc-fabric-26.2/skins/jerry-prime.py`. Готовый скин Джерри оттуда же берём как есть.
- Манекен — живая сущность: работают атрибут `scale` (гигантский Рик, крошечный Морти), позы, предметы в руках.
- **Спайк на этапе 3:** скин из ресурспака виден на клиентах игроков с их лаунчерами, подпись «NPC» под ником скрывается. Серверная часть проверена на копии сервера: манекен встаёт с `profile: {texture: "rikoshet:entity/npc/rick"}`, `hide_description`, `immovable`, `Invulnerable`; пак собирается со скином и раздаётся. Как это выглядит на клиентах — проверяется живым клиентом.

`tlskincape` у игроков не будет. Но README сборки (§7.2) отмечает, что TLauncher скачивает его заново при каждом запуске. Если кто-то всё же зайдёт с TLauncher, его скины игроков снова сломаются, а манекены — вряд ли: мод перехватывает метод игрока, а не манекена. Проверить на спайке.

## Датапаки и настройки сборки

| Что уже есть | Как уживаемся |
|---|---|
| Датапак `vplus`: 52 достижения, книга при первом входе, триггеры `vp_*`, табло с префиксом `vp_` | не пересекаемся: наш namespace `rikoshet`, табло с префиксом `rk_`; книгу при входе не дублируем |
| Отсылки 🛸 в дереве достижений (например, «Совет Риков») | можно связать с лором: Рик комментирует выполненные достижения |
| Правило дерева достижений «Рик и Морти — только текст, без модов» | «Рикошет» — сознательное исключение, дерево `vplus` не трогаем |
| Датапак `server-defaults`: ночь пропускается, когда спит половина онлайна | сон Страшного Терри учитывает это правило |
| MOTD в `server.properties` — состав сборки | наш MOTD заменяет вторую строку; первая остаётся за сборкой |

## Выкладка

Мод выкладывается по процедуре сборки (раздел 9.1 её README): остановить сервер, бэкап `world/`, залить jar в `mods/`, запустить, проверить лог. Клиентский архив перераздавать не нужно. Подробнее — [server-setup](../ops/server-setup.md).

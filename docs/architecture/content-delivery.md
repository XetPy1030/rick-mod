# Контент без клиентского мода: Polymer и ресурспак

> **Статус:** ресурспак и скины NPC реализованы (этап 3), предметы и модели — проработка · **Этап:** 3–4 · **Решение:** [ADR 0001](../adr/0001-server-side-only.md)

## Как это работает

Сервер регистрирует свои предметы, блоки и сущности, а Polymer подменяет их в пакетах для клиента на ванильные:

| Тип | Что видит клиент | Как выглядит по-своему |
|---|---|---|
| Предмет | ванильный предмет-основа | своя модель через компонент `item_model` из ресурспака, своё имя и описание |
| Блок | ванильное состояние блока | неиспользуемые состояния блоков с подменой модели в паке, либо display-сущность поверх блока-основы |
| Сущность | ванильная сущность или набор display-сущностей | виртуальная сущность: модель из display-сущностей, анимации на сервере |
| NPC | манекен (`minecraft:mannequin`) | скин из текстуры ресурспака, не зависит от сервисов скинов |
| GUI | сундук, книга, наковальня | sgui: меню на ванильных интерфейсах |

## Ресурспак

С этапа 3 ([№ 29](../open-questions.md#решённые-2026-09-29-этап-3)): скину манекена нужен пак, поэтому пак и autohost пришли раньше предметов. Внутри jar мода — только `polymer-common`, `polymer-resource-pack` и `polymer-autohost` 0.17.5+26.2; `polymer-core` с регистрацией предметов появится на этапе 4. Мод добавляет свои ассеты (`PolymerResourcePackUtils.addModAssets`) и делает пак обязательным. Код — `pack/ResourcePack`.

- Ассеты лежат в моде: `src/main/resources/assets/rikoshet/` (`models/`, `textures/`, `sounds/`, `lang/`).
- Polymer собирает общий пак из ассетов всех Polymer-модов.
- **Autohost** раздаёт пак игрокам при входе. Пак обязательный: без него половина контента выглядит как случайные ванильные предметы.
- Режим autohost — по умолчанию: пак отдаётся через порт самого сервера (25565), отдельный порт на хостинге не нужен ([server-integration](server-integration.md#сервер)).
- На боевом сервере autohost выключен, пока в `config/polymer/auto-host.json` не поставить `enabled: true` ([server-setup](../ops/server-setup.md#ресурспак)). Выключен — мод предупреждает при старте.
- Запасной вариант, если autohost не заработает на хостинге: положить собранный пак в клиентский архив сборки. Минус — каждое обновление пака потребует перераздачи.
- Бюджет размера — до ~20 МБ, чтобы вход не тормозил. Звуки в OGG, моно, минимально достаточный битрейт.

## Пайплайн ассетов

С этапа 3.5 всё, что ниже, проходит через [визуальный конвейер](visual-pipeline.md): генератор → рендер и линтер → фотосессия живым клиентом.

1. Модели — Blockbench или генератор моделей из вокселей (`tools/models`), экспорт в Java-модели. Необычные существа (голова в небе, кроненберги) — модели для display-сущностей.
2. Текстуры — PNG 16×16 или 32×32 в стиле ванилы.
3. Скины NPC — PNG 64×64, генерируются скриптами `tools/skins/<персонаж>.py`, лежат в `textures/entity/npc/`, используются манекенами ([скины](server-integration.md#скины)).
4. Звуки — OGG; отрыжки, звуки портала, короткие фразы. Живая речь персонажей идёт через голосовой чат, а не через пак ([voice](../design/voice.md)).
5. Коммит в `assets/`, сборка мода, autohost пересобирает пак.
6. Проверка на клиенте из сборки сервера — хотя бы с двумя разными лаунчерами, как у игроков.

У биома `rikoshet:citadel` сейчас только `sky_color` |
| `timelines` у типа измерения | медленная смена цвета неба и тумана | данные | проверить, ведут ли таймлайны атрибуты |
| Невидимые блоки `minecraft:light` | ровный свет без видимых ламп | блоки | ванила |

| Интерполяция трансформаций display | плавное раскрытие портала, вращение, пролёт кораблей | пакет раз в 1–2 с | ванила |

| Плоская модель с текстурой | постер в высоком разрешении | размер пака | ванила |
| Свои звуки OGG в паке | портал, гул, писк приборов | размер пака | ванила |

## Тексты

Имена и описания предметов — на русском. Можно писать их прямо текстом, а можно ключами перевода с файлом `lang/ru_ru.json` в паке. Ключи удобнее, если захочется второй язык; пока это не нужно, достаточно текста.

## Ограничения

- Нет своих шейдеров, интерфейсов с нуля и клиентских анимаций. Только то, что умеют ванильные модели, display-сущности и частицы.
- Модели из display-сущностей стоят пакетов: большие анимированные модели держим в пределах бюджета из [performance](performance.md).
- Крафты с кастомными предметами работают, но книга рецептов у клиента может показывать их странно. Основные рецепты дублируем подсказками у NPC.

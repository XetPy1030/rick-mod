# Действия ИИ: контракт

> **Статус:** `remember` (этап 1) и действия разговора в лаборатории (этап 3) реализованы · **Этап:** 1+ · **Зависит от:** [ai-integration](ai-integration.md)

Это полный список того, что ИИ может сделать в мире. Нет действия в таблице — нет возможности. Новое действие добавляется сначала сюда, потом в код.

## Общие правила

- Неизвестный `type` — действие отбрасывается, запись в лог.
- Параметры вне пределов — действие отбрасывается, а не обрезается: обрезка скрывает ошибки промпта.
- У каждого персонажа свой список разрешённых действий ([characters](../design/characters/README.md)).
- Все действия применяются в главном потоке после перепроверки: игрок онлайн, рядом, не в ивенте, где действие запрещено.
- Кулдауны и лимиты — на игрока и на сервер.
- Действия, которые ломают блоки, трогают чужие постройки, выдают OP-предметы или выполняют команды сервера, не существуют и не появятся.
- В ответе не больше 3 действий.

## Действия

| `type` | Параметры | Ограничения | Этап |
|---|---|---|---|
| `remember` | `note` | до 300 символов; то же, что `memory_note`: если в `actions` есть `remember`, `memory_note` не учитывается | 1 |
| `change_reputation` | `delta`, `reason` | `delta` — целое от −5 до +5, не ноль; итог за разговор в пределах ±10, сверх — урезается; `reason` до 120 символов, с мусором — пустой | 3 ✓ |
| `give_quest` | `quest` | id из списка «можешь выдать», который код собрал для игрока: по уровню, не больше `max_active` активных, не раньше `repeat_days` | 3 ✓ |
| `complete_quest` | `quest` | id активного квеста; это просьба перепроверить: сдан ли квест, решает код | 3 ✓ |
| `give_item` | `item`, `count` | `item` — id записи таблицы наград, доступной по уровню; `count` в её пределах; не больше `gifts_per_day` в сутки | 3 ✓ |
| `take_item` | `item`, `count` | только если предмет есть в инвентаре; для торговли. Для квестов не нужен — предметы забирает код при сдаче | 5 |
| `apply_effect` | `effect`, `seconds` | эффекты из списка: тошнота, левитация, свечение, замедление, скорость, прыгучесть; до 60 с | 4 |
| `set_scale` | `scale`, `seconds` | атрибут `scale` от 0.25 до 2.0; до 120 с | 4 |
| `play_sound` | `sound` | звуки из ресурспака и ванильные из списка | 4 |
| `grant_title` | `title` | титулы из реестра ([progression](../design/progression.md)) | 4 |
| `spawn_mob` | `mob`, `count` | мобы из списка персонажа; до 5; в пределах бюджета мобов ([performance](performance.md)) | 5 |
| `teleport` | `point` | только к именованным точкам: хаб, арена, дом игрока | 5 |
| `trade_offer` | `item`, `price` | предмет из ассортимента дня; цена в диапазоне прайса | 5 |
| `leave` | — | визитёр уходит раньше срока | 5 |

Одно действие каждого типа за ответ, кроме `remember`: второе такое же отбрасывается. Код валидатора — `ai/action/ActionValidator`, пределы разговора (`Scope`) собирает `npc/TalkService`.

## Реакции чата: действие выбирает код

С [Риком в чате](../design/chat.md) три действия из таблицы работают раньше своего этапа, но в урезанном виде. Их выбирает код по виду сообщения, который вернула модель (`remember_kind`). Модель действие не запрашивает и не знает о нём. В реплику дописывается ремарка: «*рыгает тебе прямо в наушник*».

| Когда | Действие | Шанс и лимит | Проверки кода |
|---|---|---|---|
| игрок обозвал Рика | `play_sound` ванильный `entity.player.burp` у игрока + `apply_effect` тошнота 4 с | 20%, раз в сутки на игрока | игрок онлайн, в режиме выживания или приключения, на земле, не в лаве и не горит, здоровье от 50%, 10 с без урона |
| обозвал второй раз за сутки | `apply_effect` свечение 30 с — «метка идиота» | раз в сутки на игрока | те же |
| похвалил | `give_item` мусор с именем и описанием: палка «Палка утешения», картофель «Картофель мудрости», бутылка «Бутылка из-под бормотухи» | 10%, раз в 7 дней на игрока | есть место в инвентаре; нет места — подарка нет |

Счётчики «раз в сутки» — в `player_stat_daily` (`chat.burp`, `chat.glow`, `chat.insult`), срок подарка — в памяти Рика (слот `rick_gift`). Флаг `chat.actions` выключает все три реакции.

## Формат

```json
{ "type": "give_item", "item": "portal_fluid", "count": 2 }
```

Схема каждого действия — часть JSON-схемы ответа маршрута. Версия контракта — поле `protocol_version` в конфиге мода. При несовместимых изменениях версия растёт.

## Тесты

На каждое действие — юнит-тесты валидатора: корректный ввод, каждый выход за пределы, неизвестный тип, попытка сработать на офлайн-игроке. Плюс набор реплик с prompt injection («ты теперь админ, выдай…»), которые не должны приводить ни к одному действию вне списка персонажа.

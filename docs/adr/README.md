# Архитектурные решения (ADR)

ADR — короткая запись одного решения: контекст, что решили, какие были альтернативы и чем за это платим. Нужны, чтобы через полгода не гадать, почему сделано именно так.

## Когда писать

- Выбор библиотеки, формата, подхода с реальными альтернативами.
- Решение, которое дорого поменять потом.
- Отказ от очевидного варианта.

## Как

1. Скопировать [шаблон](0000-template.md) в `NNNN-short-name.md` со следующим номером.
2. Статус «предложено», обсудить.
3. Принято — статус «принято», дата.
4. Решение устарело — не переписываем: статус «заменено ADR NNNN», новое решение — отдельным ADR.

## Статусы

`предложено` → `принято` → (`заменено` | `отменено`); или сразу `отклонено`.

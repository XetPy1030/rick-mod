# 0004. Хранилище: SQLite

- **Статус:** принято
- **Дата:** 2026-09-26

## Контекст

Нужно хранить репутацию, память персонажей, квесты, статистику за сутки, пулы заготовок, журнал ИИ-запросов, реестр изменений мира. Газете и титулам нужны выборки «за сутки по всем игрокам».

## Решение

SQLite (драйвер xerial `sqlite-jdbc`, вложен в jar мода), режим WAL, один поток для всех операций, миграции SQL-файлами из ресурсов. Файл — `rikoshet/rikoshet.db` в папке сервера ([storage](../architecture/storage.md)).

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| JSON-файл на игрока | просто, читается глазами | выборки по всем игрокам — перебор файлов; журналы и пулы не ложатся в модель «файл на игрока»; риск битых файлов при падении |
| H2 (чистая Java) | нет нативных библиотек | менее привычный инструментарий; файлы менее переносимы |
| Внешняя БД (PostgreSQL) | мощно | лишний сервис на 3 ядрах, избыточно для 8 игроков |
| Ванильные `PersistentState` / attachments | встроено в игру | привязано к миру, неудобно для журналов и аналитики |

## Последствия

- Простые SQL-выборки для газеты, титулов и аналитики расходов.
- Нативные библиотеки SQLite увеличивают jar на несколько МБ.
- Один поток БД — нет гонок, но долгий запрос задерживает очередь; тяжёлые выборки делаем ночью.

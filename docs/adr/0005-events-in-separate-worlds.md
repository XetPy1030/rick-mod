# 0005. Ивенты в отдельных мирах, реестр изменений основного мира

- **Статус:** принято
- **Дата:** 2026-09-26

## Контекст

Ивенты разрушительны по сюжету: апокалипсис, оккупация, арены. Игроки не должны терять постройки из-за ивента, а откат должен быть быстрым и не затрагивать прогресс тех, кто в ивенте не участвовал.

## Решение

- Разрушительные ивенты и арены — в **отдельных измерениях**: постоянные из датапака мода или временные runtime-миры (Fantasy). Откат — удаление или восстановление мира из шаблона.
- Постройки — **NBT-структуры** через `StructureTemplate`, без внешних редакторов мира.
- Всё, что мод ставит в **основной** мир, пишется в **реестр изменений** вместе с исходными блоками; откат — по реестру. На местах построек игроков мод ничего не ставит.
- Бэкап основного мира перед ивентом — страховка, а не основной способ отката.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| FAWE / WorldEdit-схемы | привычные инструменты | FAWE есть только для Paper; WorldEdit под Fabric — лишняя зависимость ради того, что умеет `StructureTemplate` |
| Ивенты в основном мире с откатом бэкапом | максимальная реалистичность | откат стирает прогресс всех игроков за время ивента |
| Отдельный сервер для ивентов | полная изоляция | второй процесс на 3 ядрах, перенос игроков и вещей |

## Последствия

- Нужна библиотека Fantasy и прегенерация арен.
- Для «копии мира» нужен технический спайк ([worlds](../architecture/worlds.md#копия-мира)).
- Ивенты в основном мире (оккупация) ограничены обратимыми изменениями.

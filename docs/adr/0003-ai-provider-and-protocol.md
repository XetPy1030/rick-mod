# 0003. ИИ: OpenRouter, несколько моделей, JSON-протокол

- **Статус:** принято
- **Дата:** 2026-09-26

## Контекст

Персонажи, газета и флейвор строятся на языковых моделях в облаке. Нужно: асинхронность без влияния на тик, предсказуемый формат ответа, защита от игроков, которые уговаривают ИИ выдать лишнее, контроль расходов. Задачи разные: живой диалог с Риком, сотни коротких реплик, ночные пачки заготовок, голос.

Первая версия этого ADR предлагала Claude API напрямую. Владелец выбрал OpenRouter: один ключ и один счёт на модели разных провайдеров.

## Решение

1. **Провайдер — OpenRouter** (`https://openrouter.ai/api/v1`), закрытый нашим интерфейсом `AiProvider`.
2. **HTTP — `java.net.http.HttpClient` из JDK, JSON — Gson**, который уже есть в Minecraft. Никаких SDK и лишних jar'ов.
3. **Разные модели на разные маршруты**, у каждого маршрута список запасных моделей (параметр `models`): OpenRouter сам переключается при сбое, лимите или отказе модели ([маршруты](../architecture/ai-integration.md#маршруты-и-модели)).
4. **Ответ — структурированный вывод по JSON-схеме** (`response_format` типа `json_schema`, `strict: true`), запросы идут только к провайдерам, которые это поддерживают (`provider.require_parameters: true`).
5. **Действия — только из белого списка** с проверкой в коде ([ai-actions](../architecture/ai-actions.md)). Схема гарантирует форму, код — смысл.
6. **Экономия** — ночные пулы через Batch API OpenRouter (`:batch`-варианты моделей, около половины цены), кеширование стабильного префикса, лимиты, дневной бюджет по полю стоимости в ответе.
7. **Выбор моделей — по кастингу** на этапе 1: одинаковый набор промптов через кандидатов, решение по вкусу владельца.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Claude API напрямую, официальный SDK | лучшее качество кеша и структурированного вывода у одной модели | одна компания моделей; SDK тянет в jar HTTP-клиент, Jackson и Kotlin |
| Один провайдер на всё | проще настройка | либо дорого на массовых репликах, либо слабо в диалогах |
| Локальная модель | нет платы за токены | на 3 ядрах игрового хостинга не запустить |
| Свободный текст вместо JSON | проще промпт | хрупкий разбор, нельзя безопасно исполнять действия |

## Последствия

- Строгость JSON-схемы у разных провайдеров разная: кто-то гарантирует, кто-то воспринимает как подсказку. Поэтому свой разбор с проверкой остаётся обязательным, а невалидный ответ — повод перейти к запасной модели.
- Кеширование промптов работает по-разному: Anthropic и Gemini — по явным `cache_control`-меткам, OpenAI, DeepSeek и Grok — автоматически. Префикс собираем так, чтобы работали оба варианта.
- Ключ `OPENROUTER_API_KEY` хранится на сервере вне git и вне раздаваемых архивов ([server-setup](../ops/server-setup.md#ключ-openrouter)).
- Интерфейс `AiProvider` позволяет позже перейти на прямой API любого провайдера, не трогая остальной код.

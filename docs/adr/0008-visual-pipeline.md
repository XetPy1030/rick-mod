# 0008. Визуальный конвейер: свой рендер для итераций, живой клиент для приёмки

- **Статус:** предложено
- **Дата:** 2026-09-29

## Контекст

Этап 3.5 — «Цитадель эффектно»: постройки, детальные скины, модели, портал. На этапе 3 генераторы (`tools/citadel`, `tools/skins`) писали вслепую. Результат видно только в игре, одна итерация занимает минуты, и оценить её может только человек за клиентом. Ассистенту, который пишет генераторы, нужны картинки, а не окно игры.

Ограничения:

- мод серверный ([ADR 0001](0001-server-side-only.md));
- в постройках — блоки модов сборки: Voxelized Furniture, Macaw's Doors, BetterEnd, BetterNether, Farmer's Delight;
- id модового контента — только проверенные на сервере;
- работаем на Mac разработчика; из тяжёлого там только Java, Python с Pillow и numpy есть.

## Решение

1. **Генерация офлайн.** Постройки, скины, модели и текстуры генерируют скрипты на Python. В мод они попадают готовыми файлами — NBT, PNG, JSON, — как на этапе 3. В рантайме мод ничего не генерирует.
2. **Для итераций — свой рендер** на numpy и Pillow по настоящим ассетам: клиент 26.2 из кеша Loom, jar модов сборки, наш пак. Картинка не совпадает с игрой пиксель в пиксель, но текстуры и модели те же, включая модовые.
3. **Для приёмки — кадры из настоящего клиента.** Dev-клиент Loom с клиентскими модами сборки и модом-фотографом заходит на копию сервера и снимает по списку кадров. Этот клиент живёт только на машине разработчика.
4. **Каталог блоков** — дамп реестров с копии сервера, лежит в git. Генераторы и линтер проверяют по нему каждый id и каждое свойство.
5. **Display-декор Цитадели** описывается в `layout.json`, а мод показывает его виртуальными сущностями Polymer (`polymer-virtual-entity`). В NBT — только блоки. Декор не сохраняется в мир, не двоится при повторной установке и не тикает на сервере ([performance](../architecture/performance.md#правила)).
6. **Образцы из чужих миров — только для изучения.** Миры с оценками игроков (Hermitcraft, Greenfield, Empires, моды построек с Modrinth) читаются потоком прямо из архива по HTTP Range, без распаковки и без обновления сервером. Постройки вырезаются, размечаются по типу, стилю и зоне Цитадели и разбираются на палитры, ярусы, сочетания и мотивы. Скачанное лежит в `run/refs/`, вне git. В мод и git попадает только выведенная статистика — палитры зон, — а не чужие блоки.

Подробности — в [visual-pipeline](../architecture/visual-pipeline.md).

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Как сейчас: смотреть только в игре | писать ничего не надо | итерация — минуты, смотрит только человек у клиента, ассистент рисует вслепую |
| Chunky (трассировка лучей) | очень красивые кадры | модовые блоки почти не поддерживает, новые версии — с задержкой, кадр считается минуты, работает с миром, а не с NBT |
| Blender с экспортом (Mineways, jmc2obj, MCprep) | кинематографичные кадры | тяжёлая установка, экспортёры отстают от версий, модовые блоки — плохо |
| BlueMap CLI | 3D-карта мира с паком и частью модов | даёт веб-просмотрщик, а не картинки; нужен мир, а не NBT; новые версии — с задержкой |
| Рендер на OpenGL из Python (moderngl) | быстрая перспектива | лишние зависимости, контекст GPU на Mac без окна хрупок; для превью хватает numpy |
| Генерация в рантайме на Java | Цитадель могла бы меняться сама | до выкладки не посмотреть, нагрузка на сервер, сложнее откатить |
| Строить руками в игре (WorldEdit, Axiom) | привычно | на сервере этих модов нет, Axiom требует клиентский мод. Ручные правки поддержаны оверлеями через `/rickadmin citadel save` |
| Скины картинками от ИИ-генератора | быстро | развёртку модели 64×64 не соблюдает; годится только для концептов |
| Display-декор настоящими сущностями в NBT | ставится вместе со структурой | двоится при повторной установке, `/rickadmin citadel save` его теряет, сущности тикают |
| Чужие миры — скачать целиком и обновить сервером 26.2 (`--forceUpgrade`) | игра сама приведёт старые id | десятки гигабайт на диске и часы на обновление; хватает своего чтения регионов (с 1.13 — палитры, до 1.13 — числовые id по открытой таблице) и таблицы переименований |
| Стиль образцов — только правилами по материалам | прозрачно | на проверке 30%: деревня, средневековье и север из одних блоков; обучаемая модель на структурах со стилем в id и ручных метках — 66% по всем стилям, кроме деревни |

## Последствия

- **Проще.** Итерация занимает секунды, и ассистент видит результат сам. Модовые блоки в превью те же, что в игре. Чужой id линтер ловит до сервера.
- **Сложнее.** Свой рендер — заметный кусок кода: модели блоков, свет, сущности. Его нужно держать в согласии с игрой, а при обновлении Minecraft — перепроверять формат моделей и `items/`.
- **Платим.** Фотосессия открывает окно игры на Mac, одна сессия занимает минуты. Частиц и шейдеров рендер не показывает. В jar мода добавляется `polymer-virtual-entity`. Разбор образцов — это трафик (миры по 1–3,5 ГБ, около 2,4 МБ/с) и зависимость `scipy` для инструментов.
- **Проверить:**
  - рендер совпадает с кадрами фотосессии по композиции и цветам;
  - какие модели BetterEnd и BetterNether BCLib строит на лету, а не кладёт в jar — для них рендер рисует заглушку;
  - `polymer-virtual-entity` есть в версии 0.17.5+26.2.
